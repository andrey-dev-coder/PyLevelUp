## 1. Кто такой owner

`OWNER_TELEGRAM_ID` в `.env` - это твой Telegram ID. Только владелец видит:

- команды `/panel`, `/admin`, `/broadcast`, `/broadcast_test`, `/import`,
  `/categories`, `/user_topics`, `/user_stats`, `/dm`, `/setcode`, `/reports`;
- любые callback-кнопки с префиксом `ap:`, `ape:`, `app:` (админ-панель,
  редактор, учебные планы);
- расширенные сообщения об ошибках/диагностике.

Обычные юзеры эти команды и колбэки не видят и не могут вызвать.

Узнать свой Telegram ID можно через бота [@userinfobot](https://t.me/userinfobot).

## 2. Команды

### Команды управления юзерами

| Команда | Что делает |
| --- | --- |
| `/panel` | Открывает кнопочную панель. Всё ниже доступно и через кнопки. |
| `/dm <id или @username> <текст>` | Шлёт сообщение от имени бота |
| `/user_stats <id или @username>` | Подробный отчёт: ответы, точность, стрики, mock-сессии, топ-темы, слабые темы, активность за 7/30 дней |
| `/user_topics <id или @username>` | Интерактивный whitelist категорий для юзера. Чекбоксы. Пустой = все темы |
| `/setcode <CODE>` | Задаёт глобальный код доступа (`ACCESS_CODE` в БД). Открывает все темы |

### Контент

| Команда | Что делает |
| --- | --- |
| `/import` | FSM-сценарий импорта JSON. Сначала выбор категории, потом «тесты» или «теория» |
| `/categories` | Управление кастомными категориями (создать/удалить) |

### Рассылка

| Команда | Что делает |
| --- | --- |
| `/broadcast_test <текст>` | Шлёт текст только тебе. Проверка перед массовой |
| `/broadcast <текст>` | Шлёт всем активным авторизованным юзерам. Заблокировавших бота автоматически помечает |

### Аналитика

| Команда | Что делает |
| --- | --- |
| `/admin` | Дашборд: DAU/MAU, новые юзеры, активные сессии, топ-проваленных вопросов |
| `/reports` | Открытые жалобы на вопросы (для модерации) |

## 3. Кнопочная админ-панель `/panel`

Открывает корневое меню:

```
👥 Пользователи          → три вкладки + действия с юзером
🔑 Коды доступа          → создание/редактирование/удаление кодов
📝 Редактор вопросов     → правка отдельных вопросов и теории
🛣 Учебные планы          → CRUD планов с блоками
🗑 Удалить категорию     → каскадный wipe кастомной темы
📥 Импорт вопросов       → ярлык на /import
🚩 Жалобы                 → ярлык на /reports
📊 Дашборд                → ярлык на /admin
📢 Рассылка               → подсказка по /broadcast
❌ Закрыть                → скрыть панель
```

### 👥 Пользователи

Три вкладки:

- **Активные** - `is_authorized=true AND NOT is_banned`
- **Ожидают одобрения** - `is_authorized=false AND NOT is_banned`. Это юзеры
  которые запустили `/start`, но не ввели код доступа.
- **Забаненные** - `is_banned=true`

В каждой вкладке - постраничный список (10/стр). Тык на юзера открывает
карточку с действиями:

- 📊 Статистика - тот же отчёт что `/user_stats`.
- 📂 Темы доступа - интерактивные чекбоксы (то же что `/user_topics`).
- ✅ Одобрить (только для pending) - помечает `is_authorized=true` и
  отправляет юзеру сообщение «Доступ открыт».
- 💬 Написать - FSM-ввод текста, потом бот шлёт его пользователю.
- 🔒 Забанить / 🔓 Разбанить.
- 🗑 Удалить пользователя - после подтверждения сносит из БД полностью:
  профиль, все попытки, прогресс SR, закладки, ачивки, mock-сессии,
  daily-попытки, доступы. **История чата в Telegram при этом остаётся** -
  бот не может удалять чужие сообщения старше 48ч.

### 🔑 Коды доступа

Кодовые слова с привязкой к темам. Алгоритм:

1. Создать код через ➕ Создать.
2. Вводишь строку кода (например `Backend_in`).
3. Вводишь лейбл (например «Backend»).
4. Отмечаешь чекбоксами темы, которые этот код открывает.
5. Сохраняешь.

Теперь когда новый юзер вводит `Backend_in`:

- Он помечается `is_authorized=true`.
- В `user_topic_access` ему пишется whitelist именно тех тем, что у кода.
- В `/test` он видит только эти темы.

Если код имеет пустой `allowed_topics` (или юзер ввёл глобальный
`ACCESS_CODE`), доступ открывается ко всему.

### 📝 Редактор вопросов

См. также раздел в [README.md](README.md#для-админа-owner).

Корневой экран - все категории. Поиск по всем вопросам / всей теории
сверху.

Внутри категории:

- 📝 Тестовые вопросы (N) - список с пагинацией.
- 📚 Теория (M) - список с пагинацией.
- 🔍 Поиск в категории - по тексту/ID, только в этой теме.

В списке - тык на вопрос → полный вид + действия:

- ✏️ Редактировать текст / варианты / правильный ответ / пояснение / сложность
- 🚫 Скрыть / ✅ Активировать
- 🗑 Удалить (с подтверждением, каскад)

Поиск принимает:

- Фрагмент текста (>= 2 символа) - ilike против `text`, `options` (cast to
  text), `explanation`/`ideal_answer`/`checklist`.
- `#1234` или `1234` - прямой переход к вопросу/карточке по ID.

### 🛣 Учебные планы

- ➕ Создать план: slug (короткий идентификатор) → название → описание.
- В плане:
  - Добавить блок: выбрать тему → название блока → сколько вопросов
    решить (`min_questions`, 1-200) → требуемая точность %
    (`required_accuracy`, 40-100).
  - Переименовать блок, удалить блок.
  - Переименовать план, скрыть план, удалить план.

Юзер видит свой прогресс через `/paths`. Завершённость блока считается на
лету по `attempts`.

### 🗑 Удалить категорию

Только для **кастомных** категорий. Встроенные (Python, SQL, ...) удалить
нельзя.

При подтверждении сносит:

- Все строки в `daily_challenges` с вопросами этой темы.
- Все тестовые вопросы (`questions WHERE topic=key`) + каскадом их
  attempts, progress, bookmarks, reports.
- Все теоретические карточки (`open_questions WHERE topic=key`).
- Все записи `user_topic_access` для этой темы.
- Упоминания темы в `access_codes.allowed_topics`. Если код становится
  пустым - удаляет сам код.
- Запись в `custom_categories` + чистка in-memory кэша.

## 4. Сценарии

### Новый юзер хочет получить доступ

**Вариант А - через код:**

1. Создай код через `/panel` → 🔑 Коды доступа → ➕ Создать (например
   `Backend_in` с темами Python, SQL, HTTP).
2. Отправь юзеру код в личку.
3. Юзер делает `/start` и вводит код → авторизован с whitelist'ом.

**Вариант Б - через одобрение:**

1. Юзер делает `/start`, не имеет кода, ничего не вводит.
2. Появляется в `/panel` → 👥 Пользователи → ⏳ Ожидают одобрения.
3. Открой карточку → 📂 Темы доступа → отметь нужные → ✅ Одобрить.
4. Юзеру приходит сообщение «Доступ открыт».

### Забанить тролля

`/panel` → 👥 Пользователи → активные → выбери юзера → 🔒 Забанить.
Или быстрее: знаешь telegram_id - `/user_topics <id>` тоже выведет карточку
действий (но проще через панель).

После бана юзер не сможет вызывать команды, callback-кнопки от него
игнорируются.

### Полностью удалить юзера

`/panel` → 👥 Пользователи → найди юзера → 🗑 Удалить пользователя →
подтверди.

Снесёт всё его в БД. Если потом юзер снова сделает `/start` - будет как
новый, потребуется код или одобрение.

**Что нельзя**: вычистить историю чата с ботом в Telegram у пользователя.
API не даёт этого делать. Можно только не отвечать на его новые сообщения
(автоматически благодаря удалению из БД - middleware попросит ввести код).

### Импортировать новую тему

См. раздел [Импорт контента из JSON](#5-импорт-контента-из-json).

### Подправить опечатку в вопросе

`/panel` → 📝 Редактор вопросов → 🔍 Поиск по всем вопросам → введи
фрагмент текста с опечаткой → выбери вопрос → ✏️ Текст → введи правильный
вариант.

Если знаешь ID - сразу `#1234` в поле поиска.

### Скрыть некачественный вопрос без удаления

В виде вопроса нажми 🚫 Скрыть. `is_active=false`, юзеры его больше не
получают, в `/test` он не выпадает. Чтобы вернуть - 📝 Редактор → найди
(в поиске он виден с пометкой 🚫) → ✅ Активировать.

### Создать учебный план «Backend Junior»

1. `/panel` → 🛣 Учебные планы → ➕ Создать план
2. slug: `junior_backend`, название: `Backend Junior`, описание: `Базовый
   roadmap для джуна`
3. Добавь блоки:
   - Блок 1: тема Python, название «Основы Python», 30 вопросов, точность 70%
   - Блок 2: тема SQL, название «SQL базис», 20 вопросов, точность 70%
   - Блок 3: тема HTTP, название «HTTP и REST», 15 вопросов, 65%
   - и т.д.
4. Юзер начинает с `/paths`, выбирает план, тренируется, прогресс считается
   автоматически.

### Massовая рассылка

1. Сначала тест: `/broadcast_test Привет, тест рассылки!`
2. Если ОК: `/broadcast Тут текст рассылки. Поддерживается HTML: <b>...</b>`

В конце бот отчитается: сколько доставлено, сколько заблокировали бота,
сколько других ошибок.

## 5. Импорт контента из JSON

`/import` → выбрать категорию (или создать новую через `/categories` сначала)
→ выбрать «тестовые вопросы» или «теория (карточки)» → прислать файл.

### Тестовые вопросы

```json
[
  {
    "text": "Что выведет print(type(5/2))?",
    "options": ["<class 'int'>", "<class 'float'>", "<class 'double'>", "TypeError"],
    "correct_index": 1,
    "explanation": "В Python 3 / всегда float, // - integer division.",
    "difficulty": 2,
    "external_key": "py-types-001"
  }
]
```

Поля:

- `text` (обязательно) - текст вопроса
- `options` (обязательно) - список 2-6 вариантов
- `correct_index` (обязательно) - 0-based индекс правильного варианта
- `explanation` (опционально) - комментарий который покажется после ответа
- `difficulty` (1-5, по умолчанию 2)
- `external_key` (опционально) - если не задан, бот сгенерирует hash от
  текста. Используется для upsert: повторный импорт того же `external_key`
  обновит существующий вопрос вместо дублирования.

### Теория (карточки)

```json
[
  {
    "text": "Расскажи про GIL в Python",
    "ideal_answer": "GIL (Global Interpreter Lock) - мьютекс в CPython, который позволяет только одному потоку исполнять байт-код в любой момент времени. Это упрощает работу с памятью, но мешает параллельному использованию CPU потоками. Обход - multiprocessing или асинхронность для I/O.",
    "checklist": [
      "Упомянуть CPython (другие реализации не имеют GIL)",
      "Потоки vs процессы",
      "Как обходить - multiprocessing, native libs"
    ],
    "difficulty": 3,
    "external_key": "py-gil-001"
  }
]
```

Карточки попадают в `/study` (режим карточек): юзер видит вопрос, жмёт
«Показать ответ» - открывается `ideal_answer` + чек-лист.

## 6. Переменные окружения

Полный список - `.env.example`. Основные:

| Переменная | Обязательно | Назначение |
| --- | --- | --- |
| `BOT_TOKEN` | ✅ | Токен от BotFather |
| `OWNER_TELEGRAM_ID` | ✅ | Твой Telegram ID, единственный admin |
| `DATABASE_URL` | ✅ | `postgresql+asyncpg://user:pass@host:5432/db` |
| `REDIS_URL` | ✅ | `redis://host:6379/0` |
| `CELERY_BROKER_URL` | для Celery | Обычно `redis://host:6379/1` |
| `ACCESS_CODE` | опц. | Глобальный код полного доступа |
| `DAILY_REMINDER_HOUR_UTC` | опц. | Час рассылки напоминаний (0-23) |
| `RANKING_REFRESH_MINUTES` | опц. | Интервал пересчёта рейтинга |
| `SESSION_TIMEOUT_SECONDS` | опц. | TTL активной тест-сессии в Redis (default 3600) |
| `LOG_LEVEL` | опц. | DEBUG/INFO/WARNING/ERROR |

На Railway переменные задаются в Variables секции каждого сервиса.

## 7. Миграции в проде

Railway автоматически прогоняет `alembic upgrade head` на каждом деплое (см.
`Procfile` release-phase). Если миграция упала - деплой откатывается, бот
продолжает работать на старой схеме.

Создать миграцию руками:

```bash
alembic revision --autogenerate -m "описание"
# проверь файл - autogenerate ловит не всё
git add migrations/versions/<новый_файл>.py
git commit -m "migration: ..."
git push
```

Откатить вручную (опасно, обычно не нужно):

```bash
alembic downgrade -1
```

## 8. Инциденты и troubleshooting

### Бот молчит

1. Проверь Railway: вкладка Deployments → последний билд успешный?
2. Логи: смотри `web` процесс. Скорее всего там traceback.
3. Если миграция не прошла - в логах будет `alembic.util.exc.CommandError`.
   Откати последний коммит или поправь миграцию.
4. Проверь что `BOT_TOKEN` валидный (не отозван через BotFather).

### Бот отвечает «Что-то пошло не так»

Generic ошибка, смотри логи `web` процесса в Railway. Чаще всего:

- БД недоступна (Railway PostgreSQL добавил - DB URL не обновлён).
- Redis недоступен.
- Хэндлер бросил unhandled exception - смотри traceback.

### Сессия зависла («Не могу ответить на вопрос»)

Очистить Redis-ключ сессии этого юзера:

```bash
redis-cli -u $REDIS_URL DEL "test_session:<user_id>"
```

После этого юзер делает `/test` заново.

### Кнопки не работают, callback alert «expired»

Telegram автоматически инвалидирует старые callback'и. Юзер должен открыть
актуальное сообщение и тыкать там, а не в старом.

### Юзер пишет «вы меня забанили»

Проверь: `/user_stats <id>` - покажет `is_banned`. Если да и это ошибка -
разбань через панель или прямо в БД:

```sql
UPDATE users SET is_banned = false WHERE telegram_id = <id>;
```

### Импорт сломался посередине

Импорт атомарный per-question (каждый upsert - отдельная транзакция). Если
половина вопросов ушла и потом ошибка - просто перезалей тот же JSON,
существующие обновятся через `on_conflict_do_update`.

### Бот шлёт спам / двойные сообщения

1. Проверь что только один процесс `web` запущен. Railway иногда оставляет
   старый при rolling deploy - убей вручную.
2. Long polling работает только с одним процессом. Webhook бы решил
   проблему, но мы его не используем.

## 9. Бэкапы

Railway PostgreSQL имеет автоматические бэкапы (раз в день). Их можно
скачать в дашборде Railway → Postgres → Backups.

Локальный бэкап:

```bash
pg_dump "$DATABASE_URL" -Fc -f pylevelup_$(date +%F).dump
```

Восстановление:

```bash
pg_restore -d "$DATABASE_URL" -c pylevelup_2025-05-04.dump
```

Redis бэкапить не обязательно: в нём только эфемерные FSM-состояния и кэш
активных сессий, потеря не критична (юзер просто заново сделает `/test`).
